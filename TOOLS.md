## racing_changes

Races and prices that changed since a timestamp.

- **Cost** 2 credits
- **HTTP** `GET /v1/racing/changes`
- **Parameters** `since` (required), `categories`, `country`

**Ask an assistant**

> Poll for Australian racing prices that changed in the last five minutes, and tell me what moved.

**What came back** (2026-09-14T23:45:14Z, arguments `{"since": "2026-09-14T23:40:14Z", "country": "AU"}`)

`{"credits_cost", "credits_remaining", "data"}`; `data` is an object with `races`, `server_time`

<details><summary>The description the assistant sees</summary>

```
Races and prices that changed since a timestamp. COST: 2 credits. THE RIGHT WAY TO WATCH A MARKET. Calling racing_next_to_go repeatedly re-downloads every race every time; this returns only what moved. `since` is an ISO 8601 UTC timestamp — on the first call use a recent one, then pass back the `server_time` the response returns. That cursor is set 30s behind the server clock so no in-flight write is skipped, which means the feed is at-least-once: expect to see a race twice. Note the shape — `changed_runners` is FLAT, one row per runner per bookmaker with bookmaker_key on the row, not the nested runners[].bookmakers[] of next-to-go.
```

</details>
